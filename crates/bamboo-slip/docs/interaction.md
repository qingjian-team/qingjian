# 交互层设计（2026-10-10，草案）

## 目标

现在的引擎只会「一份数据 → 一张位图」：候选窗每按一个键整棵树重建一次，只认点击命中。要让它画一个完整的应用窗口，
还缺鼠标悬停 / 按下的状态、焦点与键盘、滚动、弹出层、局部重绘，以及一个能开窗口、收事件的宿主。

第一个使用方是青简的设置程序：三个桌面平台一套代码，替掉 macOS 的 AppKit 偏好设置与 Windows 的 WinUI 3 设置程序，Linux 从无到有。
验收就是它：一页「候选窗口」设置（开关、分段选择、滑块、下拉、字体列表、主题预览）在三个平台上能用、手感不输原生。

不在这一期：文本输入与组字（放到最后单独一期）、无障碍的实际接入（这一期只在元素上留好角色与名字）、多窗口、拖放。

## 分层

```
宿主（host）        winit 开窗 + softbuffer 贴位图，系统事件 → 引擎事件，DPI、外观、减少动态效果
  ↑
控件（widgets）     按钮、开关、分段、滑块、下拉、列表、滚动区……都是普通组件，没有特权
  ↑
交互（ui）          元素树、稳定 key、事件派发、状态（悬停 / 按下 / 焦点 / 禁用）、滚动、弹出层、局部重绘
  ↑
现有核心            Scene（taffy + Visual）、Stage（过渡 / 动画 / 栅格）、TextPainter、FontLibrary
```

候选窗不走上面三层：它继续直接建 `Scene` 交给 `Stage`，交互层是附加的模块，不改现有核心的行为（青简的快照测试兜底）。

## 关键决定

### 1. 每次变化重建整棵树，靠稳定 key 接上状态

与候选窗一样，应用状态变了就重新调一遍「视图函数」建出整棵元素树，不做增量更新的保留树。理由：

- 现有核心就是这么设计的（建树 → 布局 → 画），候选窗一帧 release 1 ms，路径成熟；
- 增量树要解决「谁改了什么、子树怎么复用」，复杂度远高于一套好的缓存；
- 设置页规模（几百个节点、上百段文字）重建本身不贵，贵的是文字整形与栅格，这两样用缓存解决（见第 4 条）。

重建会让 taffy 的 `NodeId` 每次都变，所以交互状态不能挂在 `NodeId` 上。每个可交互元素带一个**稳定 key**：
由组件路径自动生成（父 key + 子组件名 + 序号），列表项可以显式给（用数据的 id，排序变了状态跟着走）。
悬停、按下、焦点、滚动位置、过渡配对都按 key 记，新树建好后按 key 认回来。现有过渡的配对名就是同一回事，统一成这个 key。

### 2. 状态在建树时就是输入，样式按状态取

元素的悬停 / 按下 / 焦点 / 禁用是视图函数的输入，控件按状态挑颜色、阴影（相当于设计稿里组件的 State 变体），
而不是在画的时候临时改样式。好处是「一个状态长什么样」完全由组件自己说了算，状态之间的过渡复用现有过渡机制。
现有过渡只插值位置大小与不透明度，状态切换要的颜色渐变需要加：节点颜色也按 key 跨帧插值。

### 3. 事件：命中 → 冒泡，处理函数产出类型化消息

- **命中**：在布局后的场景树上按坐标找最上面的节点（画序的逆序），尊重裁剪、动画姿态与「不收事件」标记；
  得到一条从根到目标的 key 路径。
- **派发**：事件先给目标，没处理就往祖先冒；不做捕获阶段，等真需要再加。
- **消息**：处理函数不直接改状态，返回使用方定义的消息枚举（`enum Message`），由应用的 `update` 统一处理，再触发重建。
  这样状态只有一个改的地方，也是以后从设计文件生成「句柄 + trait」代码时的落点：生成代码把控件事件翻成消息。
- 指针事件：移入 / 移出 / 移动 / 按下 / 抬起 / 滚轮（像素增量与行增量都要）；按下时捕获指针，拖出元素外仍归它（滑块、滚动条）。
- 键盘事件：按键 + 修饰键，先给焦点元素，没处理再冒泡；全局快捷键（⌘W、Esc 关弹层）在根上处理。

### 4. 重绘：先整窗，量过再上脏矩形

设置窗口 2 倍屏约 1800×1300 像素，整窗 CPU 重画的主要开销是阴影模糊、图片采样与文字栅格。现有缓存（效果遮罩、图片框、字形位图）已经覆盖前两样。
做法分两步：

1. 先整窗重画，加两个缓存——**文字整形缓存**（按文字 + 样式，现在每次量宽都重新整形）与**节点画面缓存**（按 key + 画面指纹）——然后量：悬停一个按钮从事件到位图出来要多久。
2. 超过预算再做脏矩形：新旧两棵树按 key 比较每个节点的「几何 + 画面指纹」，变了的节点新旧位置的并集就是脏区，只重画脏区里的节点。
   现有的循环动画局部重画（`paint_range` 分段）是同一个思路的特例，届时合并。

预算：release 下悬停 / 按下一次 ≤ 4 ms，滚动每帧 ≤ 8 ms（120 Hz 屏上能跟手）。

### 5. 滚动与裁剪

场景节点加「裁剪子节点」（矩形或圆角，圆角走 tiny-skia 的 Mask）。滚动区是一个组件：外层裁剪，内层按滚动位置平移，
滚动位置按 key 存在交互层里。触控板的像素增量直接用；惯性由系统给（macOS 惯性阶段的事件照样是滚轮事件），引擎不自己算惯性，
要验证 winit 在 macOS 上把惯性阶段的增量完整传过来。滚动条是叠在上面的组件，悬停时变粗，停止滚动后淡出。

### 6. 弹出层：先画在同一个窗口里

下拉菜单、提示、确认框先作为根节点上的覆盖层画在同一个窗口里（绝对定位 + 阴影），点覆盖层外面关掉。
限制是弹出层不能超出窗口边界；设置窗口够大，这一期接受。以后要超出窗口（比如靠近边缘的下拉）再开无边框子窗口，复用候选窗那套贴图路径。

### 7. 焦点与键盘

可聚焦元素按树序排成 Tab 顺序，Shift+Tab 反向；空格 / 回车触发按钮与开关，方向键调分段与滑块、在列表里移动。
焦点环是控件按「焦点」状态自己画的，只在键盘操作后显示（鼠标点击不显示，同 macOS / Windows 的习惯）。

### 8. 宿主

设置程序是普通的可激活窗口、独立进程，所以直接用 winit（事件循环、窗口、DPI、输入法事件将来也从它来）加 softbuffer（把 RGBA 位图贴到窗口），
三平台同一份宿主代码。原生菜单栏（macOS 的应用菜单与 ⌘Q）、文件对话框（rfd）、打开链接这类走平台 API 的小件在宿主里补。

macOS 上设置程序从输入法进程里搬出来：作为输入法包里的一个辅助程序单独启动，现在为了在后台进程里开窗而切激活策略、装编辑菜单的绕法都可以删掉。

### 9. 无障碍（只留接口）

元素带角色（按钮 / 开关 / 滑块……）、名字、值与是否禁用，交互层能列出当前的可访问树。实际接 accesskit 放到控件稳定之后。

## 里程碑

1. **窗口宿主**：`examples/window.rs` 开一个窗口，画一棵静态场景树，跟随 DPI 与深浅色；量整窗重画耗时。
2. **交互核心**：稳定 key、命中、冒泡派发、悬停 / 按下 / 焦点状态、消息与 `update`、文字整形缓存；示例里几个按钮能点、能 Tab。
3. **裁剪与滚动**：场景节点裁剪、滚动区组件、滚动条；示例里一个长列表跟手滚动。
4. **控件第一批**：按钮、开关、分段、滑块、下拉（覆盖层）、列表、分组标题；控件陈列窗口（gallery）当回归样例。
5. **设置程序第一页**：在青简仓库建 `apps/settings`，做「候选窗口」页，主题预览用 qingjian-render 画；三平台各跑一遍。
6. **重绘优化**：按第 4 条的预算决定要不要上脏矩形。
7. 其余设置页、设置项 schema 收拢，之后再开文本输入一期。

## 待定

- 动画时钟：现在 `Stage` 自己记时钟、使用方按 `next_frame` 定时调 `tick`；交互层需要的是「有动画就按显示器刷新率要帧」，宿主里用 winit 的重绘请求驱动，接口要不要改成回调。
- 文字整形缓存放在 `TextPainter` 里还是交互层里：候选窗也会受益，倾向放在 `TextPainter`。
- 颜色过渡要不要做成通用的「节点属性插值」（位置、大小、不透明度、颜色、圆角统一处理），还是只加颜色。
