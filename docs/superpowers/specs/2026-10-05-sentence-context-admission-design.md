# 整句词图：按上下文放词进格子（2026-10-05）

## 问题

`jishimu` 素笺首选「即使木」（用户机器上因个人学习显示「即使姆」），macOS 自带拼音首选「几十亩」。`shimu`、`jishimude` 同类。

## 诊断

用 CLI 加载已安装 Sujian.app 的 `dict.qj` / `lm.qj` / 含章·通变复现，逐层排查：

1. **「亩」根本进不了词图。** `sentence::viterbi::span_candidates` 每个格子只按词库一元词频留前 `SPAN_CANDIDATES` = 6 个词。
   `mu` 下按词频是 木 33643 / 姆 17870 / 母 14078 / 穆 / 目 / 墓 / 牧 / 幕 / 慕 / 莫 / 沐 / **亩 1163**，亩排第 12。
   语言模型里 P(亩|十) = e^−8.69，而 P(亩) = e^−12.37，前文「十」把它抬了将近 4 nat，但格子是按一元词频挑词的，看不到前文。
2. **神经重排看不到它。** 含章·通变单独打分时首选就是 几十亩（−2.51，即使木 −3.61），但重排只在词图前 `RESCORE_PATHS` = 6 条里挑，
   而词图里根本没有含「亩」的路径。把重排条数加到 32、λ 加到 1 都翻不过来。
3. **词库与二元模型都偏小。** `dict.tsv` 9.3 万条，没有 几十 / 十亩 / 几十亩；二元模型稀疏，「是木」压过「师母」也是这个原因。
   这一层是本 spec 之外的后续工作（见「后续」）。

只把 `SPAN_CANDIDATES` 从 6 改成 16，`jishimu` 接上通变后就是 几十亩、`jishimude` 不接模型也是 几十亩地，说明第 1 条是根因。
但这样整句评测反而变差（见下表）。

## 为什么不能直接放宽

`data/eval/sentences.tsv`（1878 句，冷启动，不接模型）上逐条对账，放宽后翻错的 40 条几乎都是**多音字的冷门读音**混了进来：
或 → 和（和/huo 3612，和/he 904295）、模式 → 没是（没/mo）、拼音行 → 拼音省（省/xing）、词库 → 差哭（差/ci）、云联想 → 云林县。

根源是二元模型按**词文本**计数，不分读音：P(和|X) 统计的几乎全是 he 读音的「和」，拿来给 huo 读音的「和」打分就大大高估。
原来 6 个的上限恰好把这些冷门读音挡在外面，放宽后它们靠「和」的文本概率混进路径。

## 设计

格子分两段：

- **首段**：按一元词频（加用户选择次数、个人出现次数，替代写法打折，与现在一样）的前 `SPAN_CANDIDATES` = 6 个，无条件进词图，行为不变。
- **候补段**：接下来到第 `SPAN_POOL` = 16 个为止。候补词进词图要同时满足两条：
  1. **读音占比**：这个读音的词频占该词全部读音词频之和不低于 `MIN_READING_SHARE` = 0.5。亩/mu 占 100% 能进，和/huo 0.4%、没/mo 0.8% 进不来。
     这是给「二元模型不分读音」打的补丁：只有读音几乎唯一的词，文本概率才代表这个读音的概率。
  2. **前文抬举**：`nodes[start]` 里至少有一个前驱 p，使静态模型的 log P(w|p) 严格大于 log P(h|p) 对首段所有 h 取的最大值。
     也就是说，在某个前文下它比首段里最好的那个还可能，才值得占一个格子。只看静态模型（不认识就用词库兜底），不看个人 n-gram：
     个人常用的词已经通过 `seen` 进了首段。

简拼格子（已经留 `ABBREVIATED_SPAN_CANDIDATES` = 20 个）不走候补段。候补段只决定**能不能进格子**，进了以后打分与首段的词完全一样，
路径分、`static_score`、神经重排、束宽剪枝都不改。

### 读音占比从哪来

`Dictionary` 加 `text_frequency(text) -> u64`：同一个词文本在本词库所有读音下的词频之和。
内部是懒建的 `TextTotals`（`OnceLock`，词文本 → 词频和），第一次整句转换时从 `entries()` 建一次，9.3 万条约几毫秒、几 MB，
不改 `.qj` 格式，不影响启动。多个词库（主词库 + 领域词库）时分母是各词库之和，分子是命中那条的词频。

`SpanWord` 加 `reading_share: f64`，在 `span_candidates` 里算好随格子进 `SpanCache`；前文抬举依赖 `nodes[start]`，每次在 `convert_paths` 主循环里现算，不进缓存。

### 常数

| 常数 | 值 | 位置 |
|---|---|---|
| `SPAN_CANDIDATES` | 6（不变） | `sentence/mod.rs` |
| `SPAN_POOL` | 16 | `sentence/mod.rs`，新增 |
| `MIN_READING_SHARE` | 0.5 | `sentence/mod.rs`，新增 |

## 原型数字

原型在 `viterbi.rs` 里用环境变量扫参数（不提交），`data/eval/sentences.tsv` 1878 句，冷启动：

| 配置 | 首选 | 前三 | 字准确率 |
|---|---|---|---|
| 基线（6） | 32.7% | 38.3% | 76.8% |
| 直接放到 16 | 31.3% | 36.4% | 75.9% |
| 16 + 前文抬举（门槛取首段最小值） | 31.3% | 36.5% | 75.9% |
| 24 + 前文抬举（门槛取首段最大值） | 31.4% | 36.6% | 76.0% |
| 24 + 只看读音占比 0.5 | 32.9% | 38.2% | 76.8% |
| 24 + 读音占比 0.5 + 前文抬举（最大值） | 33.0% | 38.6% | 76.9% |
| **16 + 读音占比 0.5 + 前文抬举（最大值）** | **33.1%** | **38.9%** | **77.0%** |
| 接通变：基线 | 37.5% | 40.1% | 79.1% |
| 接通变：24 + 读音占比 + 前文抬举 | 37.7% | 40.6% | 79.3% |

占比 0.3 / 0.5 / 0.8 结果相同，取 0.5；前文抬举加 1 nat 余量没有区别，不加。
逐键计时（57 键长句，原型用 TSV 现读做分母）平均 643 µs → 1.08 ms，实现改成懒建表后要重测。

`jishimu`（接通变）→ 几十亩，`jishimude` → 几十亩地，`jishige` → 几十个 不变。

## 验收

- `jishimu` 接通变首选 几十亩；`jishimude` 不接模型首选 几十亩地（CLI，产品数据）。
- `sentences.tsv` 冷启动首选、前三、字准确率都不低于基线，接通变同样不低于基线。
- 输入日志回放（`--replay data/eval/input-log-2026-10-04.jsonl`）词首选、整句首选不低于基线。
- `--typing` 长句平均每键增幅不超过 0.5 ms，最慢一键仍在 10 ms 以内（release）。
- 单元测试：低频单读音字靠前文进格子；冷门读音即使前文强也进不来；首段行为不变。

## 不做

- 不改二元模型、不按读音重训（真正的根治，但要重做语料管线）。
- 不改神经重排的路径数与公式，不把模型生成的整句塞进重排池。
- 不碰简拼格子。

## 后续（各自单独提）

1. **补词库**：从 `data/corpus` 挖高频、内部结合紧（PMI）的字串，补 几十 / 十亩 这类常用组合。
2. **读音感知的二元模型**：语料按词库读音标注后再统计，或者在 `LanguageModel` 上乘读音占比，届时本 spec 的占比门槛可以撤掉。
3. **生成的整句参与排序**：干净拼音也让通变生成，模型分领先重排首选一定余量时放第二位；先在评测上量。
