AI 服务也可以不用服务商，改由这台电脑上的模型提供：在「设置 → 云服务」选一个 GGUF 模型文件，青简用 [llama.cpp](https://github.com/ggml-org/llama.cpp) 的 llama-server 在本机运行它。
[AI 服务](index.md#能做什么)的各项功能都可使用，请求只在本机处理，不联网，不需要 API 密钥，也不产生费用。

macOS、Windows、Linux 支持；Android 不支持。

## 准备

- **内存**：需要的空闲内存比模型文件大 1 GB 左右。
- **速度**：Apple 芯片的 Mac 与带独立显卡的电脑上最快；只用 CPU 也可使用，第一次请求需多等一些时间，见[速度与内存](#速度与内存)。
- **模型**：联想要求回复快，宜选 2B 至 4B 的小模型，如 Qwen3.5-2B。

## 安装 llama.cpp

需 llama.cpp b10141 或更新的版本；Windows 上模型的文件路径含中文时，需 b12010 或更新的版本。

| 系统 | 安装方式 |
|---|---|
| macOS | 在终端执行 `brew install llama.cpp` |
| Windows | 在终端执行 `winget install ggml.llamacpp` |
| Linux | 从 llama.cpp 的 GitHub 发布页下载 Linux 版压缩包并解压，或在终端执行 `brew install llama.cpp`（已装 Homebrew 时） |

青简在系统的程序路径（PATH）与 Homebrew、winget 的安装位置里查找 llama-server，用上面的命令安装后无需另行设置。
程序放在别处（如 Linux 上解压的文件夹）时，在「设置 → 云服务」的「llama-server」一项点「选择…」指定它。

## 下载模型

模型是一个扩展名为 `.gguf` 的文件，可在 Hugging Face 或魔搭社区（ModelScope）搜索「模型名 GGUF」下载，如 Qwen3.5-2B 的 GGUF 版本中的 `Qwen3.5-2B-Q6_K.gguf`。
文件名里的 Q4、Q5、Q6、Q8 是量化档位：数字越小，文件越小、速度越快，质量略有下降。2B 的模型选 Q6_K 较为均衡。

## 开启

1. 打开「设置 → 云服务」，在「本机模型」一项点「选择…」，选中下载的 `.gguf` 文件。也可将文件路径粘贴进输入框，按 `Enter` 保存。
2. 打开「启用」。青简随即在后台启动 llama-server 并加载模型，加载需几秒至几十秒，其间不出 AI 候选。
3. 点「测试连接」：等模型加载完成后发送一条最短的请求，成功时显示模型名与耗时。

选了本机模型后，「接口地址」「模型」「API 密钥」三项变灰，不再使用；清空「本机模型」即改回使用服务商。

本机模型的请求同样计入[AI 服务用量](../learning/statistics.md#AI-服务用量)，不产生费用。

llama-server 由青简启动与关闭：关闭「启用」、清空「本机模型」或退出输入法时，llama-server 随之退出并释放内存。llama-server 意外退出时，青简隔一段时间自动重新启动它。

## 速度与内存

- 第一次请求需处理整段提示，只用 CPU 时可能需要十几秒，超过请求的等待时间（缺省 5 秒）时这次不出结果，「测试连接」显示超时；之后的请求复用已处理的部分，快得多。若一直超时，可在配置文件中延长等待时间，见[直接编辑配置文件](../advanced/config-file.md#AI-服务)。
- 青简已关闭模型的思考：Qwen3.5 这类模型缺省先思考再回答，会使回复变慢或为空。
- 若需只用 CPU、限制占用的线程数或减少内存占用，可在配置文件中给 llama-server 追加参数，见同一节。
- 电脑有几块显卡时，llama.cpp 缺省把模型分到所有显卡上。只想用其中一块，或自己编译的 llama.cpp 只支持其中一块时，在配置文件中用 `local_env` 指定显卡，见同一节。
- 平时用脚本启动 llama-server 的，把脚本里的参数写进 `local_args`、环境变量写进 `local_env`，青简启动时一并带上；地址、端口与模型名由青简指定。

## 隐私

llama-server 只接受本机的连接，同一网络中的其他设备无法访问。青简关闭了它查看请求内容的接口，并只允许同源的浏览器请求，浏览器中打开的网站无法借它读取打过的字。
请求内容只在本机处理。llama-server 的输出中只有加载过程与每次请求的耗时，不含请求内容。

## 使用已有的本机服务

已自行运行 llama-server、LM Studio、Ollama 这类本机服务时，也可以不选模型文件，而将「接口地址」填为该服务的地址（如 `http://127.0.0.1:8080/v1`），「模型」填它的模型名。
本机地址不需要 API 密钥，也不经过系统代理。这种情况下服务的启动与关闭需自行负责；模型若缺省思考，需在服务中关闭思考。

## 问题排查

「测试连接」失败时显示原因：

| 提示 | 处理 |
|---|---|
| 找不到 llama-server | 安装 llama.cpp，或在「llama-server」一项指定程序 |
| 找不到模型文件 | 文件已被移动或删除，重新选择 |
| 端口被别的程序占着 | 在配置文件中换一个端口，见[直接编辑配置文件](../advanced/config-file.md#AI-服务) |
| llama-server 退出了 | 后面附有 llama-server 自己的报错；含 `invalid argument` 时多为 llama.cpp 版本过旧，需更新 |
| llama-server 退出了：CUDA error: no kernel image is available… | 用到了这个 llama.cpp 不支持的显卡，多见于有几块显卡时；用 `local_env` 只让它用支持的那块，见[速度与内存](#速度与内存) |
| 模型还没加载完 | 稍后再测 |
| 本机模型若干毫秒内没有回复 | 见[速度与内存](#速度与内存) |

llama-server 意外退出时，它最后的输出记在运行日志里；打开「设置 → 高级 → 详细日志」后，它的全部输出都记进运行日志。日志位置见[数据文件与日志](../advanced/data-files.md#运行日志)。
