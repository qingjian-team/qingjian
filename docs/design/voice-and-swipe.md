# 语音与滑行输入

手机特有的两种输入方式（2026-10-20）。框架先搭好：入口、界面、设置项和跨平台接口都已定下，识别与解码的实现往里填，只换实现，不动入口与界面。语音已接上火山引擎的云端识别，滑行按词表给轨迹打分解码。
Android 上怎么接的见 [notes/android.md](../notes/android.md)「语音输入」。

## 分工

按 [contributing.md](../contributing.md) 的约束：以后各平台都能用的部分放 Rust，平台壳只做平台相关的事。

| | Rust（各平台共用） | 平台壳 |
|---|---|---|
| 语音 | 识别结果上屏 `Engine::commit_voice`；云端与本地离线识别实现 `qingjian_core::Transcriber`（云端在 `qingjian-voice`） | 录音、系统自带的识别器、麦克风权限、语音面板、识别服务的设置页与密钥保管 |
| 滑行 | 解码 `qingjian_core::SwipeDecoder`（轨迹 + 键位几何 → 字母串），解出的字母经 Session 像点按一样进组句 | 判定点按还是滑行、记轨迹、画轨迹、交键位几何 |

## 语音

### 识别结果怎么回到输入框

不论哪种识别方式，最终结果都经 `Engine::commit_voice` 上屏：繁体输出开着时转繁体，记进输入历史（云联想的上文）、例句、输入日志（来源 `voice`）和输入统计。
统计里语音按字数与切出来的词数算，不算选词，也不计键数与时长，所以首选率、码长这些打字指标不受影响。不记词频：识别结果不是从候选里挑的。

说话途中的中间结果只是显示，不进 Core：壳把它作为编辑中的文字放进输入框，最终结果上屏时替换掉；取消就撤掉。

### 识别方式

能装下四类识别方式，入口与界面不用改：

- **系统识别器**（Android `SpeechRecognizer`、iOS `SFSpeechRecognizer`）：平台 API，实现留在壳里。
- **调系统语音输入法**：把输入法临时切过去，结果由那个输入法直接写进输入框，壳里实现，不经 Core。
- **云端识别**、**本地离线模型**：各平台都能用，实现 Core 的 `Transcriber`，放独立 crate（与云联想一样，Core 本身不联网）。

`Transcriber` 是非阻塞接口：`start(采样率)` → 若干次 `feed(单声道 16 位 PCM)` → `finish()` 或 `cancel()`，结果由壳定时 `poll()` 取，事件是中间结果、最终结果、出错三种。
`available()` 为假时入口只提示「还不能用」。

### 云端识别：火山引擎豆包流式语音识别

现在接的第一个识别服务（2026-10-20），在 `crates/qingjian-voice`：豆包流式语音识别模型 2.0，走大模型流式识别的 WebSocket 接口（`bigmodel_async`，结果有变化才回包）。

- 一段识别一条连接，开在后台线程上：连上时带 `X-Api-Key`（新版控制台的 API Key）与 `X-Api-Resource-Id`（小时版 `volc.seedasr.sauc.duration` 或并发版 `.concurrent`），先发识别参数（PCM 16 kHz 单声道、标点、数字规整、二遍识别），再每 200 ms 发一包音频，说完发负序号的最后一包，等带「最后一包」标志的回包当最终结果，8 秒没等到算超时。
- 帧是 v3 二进制协议（4 字节头 + 序号 + 长度 + gzip 载荷），回包里取 `result.text`（整段，不是增量）当中间结果。
- 加密连接用 rustls（ring + 内置根证书），桌面与安卓同一套，不依赖平台证书库。
- 配置（服务、密钥、计费方式）是平台设置里单独一页，与云联想、翻译用的大模型配置分开：两者是不同的服务、不同的密钥，用户可能只开一样。
- 出错（密钥无效、没网、服务繁忙、超时）交回一句给用户看的话，入口照常收起面板。

本机离线识别以后作为另一个识别服务加进同一个设置项，用户自己选：离线不联网、不花钱，云端更准。

### 交互

- 入口：按住空格不动约 400 ms（键盘设置「长按空格说话」，缺省开）、工具栏的话筒、全面屏底栏的语音键，三处进同一个入口。
  按住空格后横向滑动超过一格是移动光标，与语音不冲突；语音开不起来（还不能用、没有权限）时按住空格照旧移动光标。
- 面板盖住候选条与键盘：底板上一团主题色的光，上方一条随音量起伏的细波形，中间一段弧分两块，左「撤回输入」、右边照搬输入框回车动作的文字（发送、搜索…，多行框没有动作，写「完成」），下面一行提示、一个圆钮，最底一排 ⌄ 与键盘图标。
- 按住空格说话：手指滑到哪块上松手就是哪个——「撤回输入」撤掉编辑中的字，右块上屏后执行回车动作（聊天框里即发出），别处松手只是说完、上屏。
- 点按进来：两块弧都能点；圆钮（画话筒）与键盘图标是说完、回到键盘；⌄ 是说完、上屏后收起键盘。
- 要录音的识别方式先查麦克风权限，没有就开一个透明窗口弹系统权限框（输入法服务弹不了），给了直接开始。

## 滑行

### 范围

只给拼音全键盘与英文键盘（26 键），设置「滑行输入」缺省关。九宫格、注音不是字母键；双拼、五笔的字母不是这样拼词的，日语暂不给。

### 解码接口

壳交两样东西：轨迹（一串点）与各字母键的中心和大小，坐标是壳那边的像素，同一个坐标系即可。键位每次随轨迹一起交，不在 Rust 里另存一份键盘布局：键盘高度、全面屏、横竖屏一变键位就变，跟着交最省事，将来键盘统一到 Rust（Phase 5）时再改成直接读。

`SwipeDecoder::decode(轨迹, 键位, 候选词)` 按可能性从高到低回几个小写字母串，现在只用第一个。解出的字母像一个个点出来的一样进组句（拼音照常切音节、出候选，英文照常出英文词），所以候选、选词、学习、统计都不用为滑行另做；英文键盘不组句时字母串直接上屏。

候选词（`SwipeLexicon`：字母串加 log10 词频的先验）由调用方按当前在打什么给，解码本身不知道中英文：

| 在打什么 | 候选词 |
|---|---|
| 中文（拼音全键盘） | 主词库每个词的音节连起来（`zhongguo`），同一串的各词词频相加；单音节也在里面 |
| 英文模式、字母直接上屏 | 随包英文词表，词频是 Zipf × 1000 |
| 日语（现在键盘上不开滑行） | 空：没有词可比，退回按拐点取字母的 `CornerDecoder` |

两份词表在第一次滑行时才建（各几十毫秒），之后常驻；用户自己打过的词、附加词库不收，新词点按打。

`ShapeDecoder` 的打分（实现见 `swipe/shape.rs` 文件头）：每个候选词依次连起各字母键中心是它的「理想路径」，坐标按键宽高归一，形状差是几项距离平方之和——两条线按长度重采样成 48 个点逐点比的均方、词的字母按顺序在轨迹上找最近点的均方（直线顺路划过的字母也算经过）、轨迹离理想路径最远的一点（轨迹拐去的地方词里得有字母，`nihao` 不解成 `niao`）、起点与终点各自离首尾字母的距离（`hello` 与 `help` 只差终点一个键）。总分是 `先验 − 5 × 形状差`。

- 只比首尾字母键在起点、终点 1.1 个键宽内的词（按首尾字母分桶），路径长度与轨迹差太多（超过 1.8 倍再加一个键宽）的跳过。
- 起终点的差只取决于首尾字母，`先验 − 5 × 起终点差` 是总分上限：按上限从高到低比，上限不如第五名、或比第一名低 6 分以上就停；一个词的几项按便宜到贵算，超了预算就停。随包词表上电脑一次不到 1 ms，最长的词几毫秒。
- 同一个键连着两次（`ll`）在路径上是同一个点，靠词频分：`hello` 比 `helo` 常用；`to` 与 `too` 形状一样，取更常用的 `to`。
- 用带噪声、抄近路的模拟轨迹在随包词表上评过：英文 54 个常用词、拼音 50 个常用音节串与词，首选对的英文约 98%（错的是 `too`、`there`）、拼音约 99.6%，正确的词都在前五。

以后可以加上前文的语言模型（整句接着前一个词打分）与用户词，接口不变。

### 交互

- 手指落在字母键上就开始记点，离起点挪开 0.6 个键宽才算滑行；之前照常是点按（按下态、气泡、长按选符号都在）。转成滑行时撤掉按下态与长按。
- 滑行时画一道主题色的线，抬手交给解码、线消失。
- 第二根手指在滑开之前落下，说明是在快打，这一笔不当滑行；滑开之后落下的手指不理。
