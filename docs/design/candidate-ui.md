# 候选窗口设计

## 布局

候选窗口缺省竖排（配置 `[general] layout`，可选横排）。竖排时每个候选项由两个主要部分组成：

```text
候选词                     翻译
```

例如：

```text
1  计算机                  computer
2  电脑                    computer
3  计算                    calculate
4  计算器                  calculator
```

横排时候选排成一行，只给高亮的那个在下面单独一行显示译文（每个都带译文会把窗口拉得很宽），页码在行尾：

```text
1 计算机  2 电脑  3 计算  4 计算器          1/3
computer
```

顶部都有一行拼音（preedit），见下文「拼音行」。

## 视觉层级

- 候选词：较大、较深
- 翻译：较小、较浅
- 序号：弱化显示
- 当前候选：轻量高亮

翻译永远不应该抢夺候选词本身的注意力。它只是一个 annotation，而不是另一套候选系统。

## 翻译 annotation 的规则

- 一个候选只显示一条译文，语言由用户配置的 Learning Language 决定。
- 译文缺失时该行留空，不显示占位符，不显示「加载中」。
- 译文尚未就绪时候选窗口照常显示，译文到达后再补画，不等待。
- 译文的具体取舍策略（词典词才标注、一词多义取最高频义项）见 [architecture.md](architecture.md)。
- **生词**用强调色（橙）画译词本身，不加图标不加文字：一条译词在用户上屏时出现在候选窗口里的轮次不到 3（Core `FRESH_UNTIL`）就算生词，
  看熟了自动变回译文色。「看到」按上屏那一刻屏幕上那一页算（壳每次画完 `Engine::note_displayed` 告知当前页，上屏时才记），
  逐键刷新时一闪而过的不算。判断与记录都在 Core（`VocabularyTracker`，`Sense::fresh`），壳只是按 `Tone::Fresh` 换颜色；
  英文模式候选的中文释义不是学习语言，不参与。

## 技术选型

候选窗口本质上只有四个原语：若干行 (序号, 候选词, 译文)、一行高亮、跟随光标定位、异步补画译文。
这么小的 UI 不值得引入跨平台 GUI 框架，每个平台用原生绘制，几百行以内。

| 平台 | 方案 | 理由 |
|---|---|---|
| macOS | `objc2-app-kit`：非激活的 NSPanel + 自定义 NSView，用 NSAttributedString / Core Text 画行 | Squirrel 同款做法。窗口必须不抢焦点、浮在所有应用之上、瞬间出现，只有 AppKit 能稳定满足 |
| Windows | Server 进程里用 Direct2D + DirectWrite 画到 layered window | Weasel 同款做法。避开 WebView2 依赖（水杉 issue #68 就是安装环境缺 WebView2） |
| Linux | 自绘窗口（wayland-client / x11rb），不用 IBus / Fcitx 自带面板 | IBus 的 lookup table 没有 comment 字段，Fcitx5 有但样式受面板限制。kime 走的也是自绘 |

macOS 面板的层级与 Space：层级 `kCGPopUpMenuWindowLevel`（101，与系统候选框同级；不能 `setFloatingPanel`，它会把层级改回 3，全屏应用里就看不见），
collection behavior 是 CanJoinAllSpaces + FullScreenAuxiliary + Stationary。但 macOS 26 上 WindowServer 只把面板绑到它**创建时已有**的 Space：
登录时建的面板只在桌面 Space 上，之后新开的全屏 Space（Zed 全屏）里没有它，候选框留在桌面、全屏里看不见（2026-09-07 用 CGS `CGSCopySpacesForWindows`
查实：面板的 Space 列表只有桌面那一个，同样设置新建的面板却是全部 Space；重设 collection behavior、收起再排前都不能让它重算）。
所以每次 `orderFront` 后查 `isOnActiveSpace`，不在就把内容视图搬到一块新建的面板上再排前，并记一条 warn（`candidates/window.rs`）。
诊断脚本在 `target/diag/spaces.swift` 一类的临时位置，不进仓库。

不选的方案及原因：

- **WebView（水杉 HTML UI 的路线）**：样式最自由，但常驻进程多一个渲染引擎，首次弹窗有可见延迟，
  且引入平台运行时依赖。候选框是「打字时每秒弹好几次」的 UI，延迟比样式重要。
- **egui / iced / GPUI 等 Rust GUI 框架**：它们假设自己拥有窗口和事件循环，
  和「非激活浮层」这种系统级窗口语义打架，为几百行绘制引入整套框架不划算。

主题化通过配置（字体、字号、前景背景色、行距、圆角）实现，不提供 HTML/CSS 皮肤。

## 平台层的职责

候选窗口由平台层绘制，但候选内容、顺序和译文全部来自 Core。
平台层拿到的是已经排好序、已经带好 annotation 的候选列表，只负责画。

## 按键约定（macOS 已实现，其他平台照此）

| 按键 | 行为 |
|---|---|
| 字母、`'` | 在光标处插入 |
| 空格 | 上屏高亮候选；无候选时上屏拼音 |
| 1 到 9 | 上屏当前页第 N 个 |
| 回车 | 上屏拼音本身 |
| 退格 / Delete | 删光标前 / 后一个字母 |
| ⌥⌫ / ⌘⌫ | 删光标前一个音节（全拼按最优切分的最后一个音节连同 `'`，切不动的尾巴整个删；双拼两键一音节；直输段按字母段）/ 删光标前全部拼音（`Engine::delete_syllable_backward` / `delete_to_start`）。不在组句时交给应用，撤销的账不再记（`break_chain`） |
| Esc | 清空 |
| 上 / 下 | 移动高亮，到页边自动翻页；第一项再按上不动 |
| ⌥← / ⌥→ | 按音节跳光标（边界规则同 ⌥⌫；`'` 跟着前面的音节，`Engine::move_cursor_syllable_left` / `right`）。光标在末尾发现前面的音节错了：⌥← 跳过去、⌥⌫ 删掉重敲、⌘→ 回末尾 |
| 左 / 右、Cmd+左 / 右 | 移动拼音光标（不切模式）。光标停在中间时候选只按光标前的拼音算（`ni|hao` 出 你），上屏后剩余拼音留着、光标落到末尾；光标在开头或末尾按整段算 |
| PageUp / PageDown、Shift+Tab、翻页键对（配置 `[general] page_keys`，缺省 `[` `]`，可选 `,` `.`） | 翻页。每页几个由 `page_size` 定（1–9） |
| 半角标点（`is_ascii_punctuation`，翻页键除外；⇧+数字已被删候选 / 译词键截走） | 组句中敲它进入**英文直输段**：`no-way` `hello,` `dui'ma?` 整段原样显示，之后的可见字符（含数字、大写）都追加，回车原样上屏，空格原样上屏后空格本身也交给应用（`hello, world` 的空格要在），Esc 清掉。表达式 / 问字模式优先。中文模式下就能打带标点的英文句子；代价是没有了「拼音 + 标点 = 上屏候选 + 全角标点」，要先空格再打标点 |
| Tab | 有整句补全（云联想）时接受它；没有则翻页 |
| 修饰键 + 数字（⌥ / ⇧⌥ 上屏译词、⇧ 删候选） | **只在组句中认**。不在组句时 ⇧4 就是普通的 `$`，走中文标点规则出 ￥（⇧1 ！、⇧6 ……、⇧9 ⇧0 （ ））；曾经在这里被截走后原样还给应用，全角转换就漏了 |
| 按住 Shift 打的大写字母 | 先把拼音原样上屏，再原样交给应用（临时打英文） |
| ⌥ + 1–9 / ⇧⌥ + 1–9 | 上屏当前页第 N 个候选的**译词**而不是候选本身：⌥ 第一条，⇧⌥ 第二条（候选右侧有两个译词时）；日文不带注音；学习与拼音消耗同选了那个候选。没那条译词的候选吞掉按键不动。两组修饰键在配置 `[shortcut] translation` / `translation_second`（任意修饰键组合，偏好设置「快捷键」页点按钮录制），两组相同或为空整个退回缺省；说明里提醒避开 ⌃+数字（系统切桌面）和 ⌘+数字（应用切标签页）。控制器在 `handleEvent:client:` 里按键码认数字（修饰键会把数字变成 ¡™£），其余按键自己分发成 `handle_text` / `handle_command`。不能改用第二层协议 `inputText:key:modifiers:client:`：那会把回车、方向键当文本送来 |
| ⇧ + 1–9（可改） | **删掉当前页第 N 个候选**：自己造的词、云端选过的词（用户词）整个删掉，本地不再出；词库里的词清掉对它的全部学习（选择次数、各输入串下的选择、个人 n-gram 里与它有关的转移），回到原来的排序；整句 / 快捷候选 / emoji 没什么可删。删完重新查一遍，结果那句话（「已删除用户词「X」」）灰字显示在拼音行右侧，敲下一键就没了；那格没有候选就吞掉按键。修饰键在 `[shortcut] delete_candidate`（缺省 ⇧，与译词键撞了退回缺省）。代价是组句中 ⇧1 不再是「上屏 + ！」，要先上屏；Core `Engine::forget` → `Learner::forget` / `forget_english` |
| ⌃⌥T（可改） | **翻译选中的文字**：不在组句中、应用里有选区（≤ 500 字符）时，把选区交给云端翻译（`PredictionKind::Translate`，`Engine::request_translation`）：选区主要是汉字译成学习语言，有假名或拉丁字母不少于汉字就译成中文（Core `prediction::translation_target` 按字符统计定方向，提示词兜底「已是目标语言就译成中文」），候选窗口先显示「翻译中…」，译文到了作为唯一候选显示；回车 / 空格 / 1 用译文替换选区（`insertText:replacementRange:`），Esc 保留原文，其他键放弃并照常交给应用。云服务关着、密码框、应用不支持读选区（部分 Electron）时快捷键原样交回应用。快捷键在 `[shortcut] translate_selection`（修饰键 + 一个字母或数字，任意组合，偏好设置「快捷键」页录制；缺省 ⌃⌥T 避开了 ⌘T 这类应用常用键） |

### 整句转换（离线）

最优切分至少两个音节、且最优路径不止一个词时，整句放在第一位（空格上屏的就是它），`CandidateKind::Sentence`：
`jintiantianqihenhao` → 今天天气很好，`womenyiqiqukaifa` → 我们一起去开发。整段本身是词库里的词时不出整句。
打分是静态 bigram（`qingjian-lm`）与个人 n-gram（二元 + 三元，看前两个词）插值。简拼位置照转（`jttqhh` → 今天天气很好，`wjdzjsg` → 我觉得自己是个），
每个简拼格子按前缀多留一些词、由语言模型挑读音；两字母简拼多半还是词（`sj` 时间），单词路径得分高就不出句子。
全拼句子末尾未打完的音节至少两个字母才算进句子（`woxiangs` 多半是没打完的 shuo），前面已有简拼的句子末尾单字母就是一个音节（`wxq`）。
有音节连单字都查不到（只能拿拼音占位）的不出句子；整段是英文词或不像拼音带出的英文补全排在句子前面（`hello` 先英文再 荷兰咯）。
上屏按音节消耗拼音，路径上的词逐条记进个人 n-gram（`user-ngram.tsv`），不记词频。

**越用越像自己**：连续上屏的词（整句里的、或一个个选的）都记成「前词 → 后词」，同时记「前二词 前词 → 后词」；`qingjian` 里选过两次 青 + 简，
再打 `qingjian` 整句就直接出 青简（个人转移压过静态模型里的 请见）。三元分辨二元混在一起的接续：「我想」后面选过几次 区，
`woxiangqu` 就出 我想区，而「不想」后面照旧。标点、回车上屏拼音、切应用都断句，之后的词按句首记。
**自动造词**：自己连着选出的两个词合起来词库里没有（不超过 4 个字），同一段拼音里连着选两次、或分两段打三次，
就记成用户词（`user-words.tsv`），之后按词出、靠选择次数排前。

### 英文模式候选

Caps Lock 亮着（英文模式）敲字母时也组词：字母（以及组词中的数字、`_` `'` `-`）进缓冲区、原样显示，候选来自英文词表
（Core `english::suggest`）：整段正好是的词第一（按词表写法），然后是前缀补全，4 个字母起再给差一处编辑（换 / 多 / 少一个字母、相邻对调）的纠正
（`recieve` → receive，`seperate` → separate）；后两组各按选过的次数、词频排。大小写跟着敲的走：`Compa` 出 Company，`COMPA` 出 COMPANY。
带数字或符号的（`foo1`）是标识符，不猜。emoji 照配，但排在所有词后面（上下键选词时不挡路）。

按键约定与中文模式的关键差别：**空格、回车、标点都原样上屏敲的字母**（再把那个键交给应用），数字键还是数字——所以不选词时它和纯直通完全一样，
写代码、打标识符不受影响；**选词靠 Tab（选高亮项）和上下键**，用上下键动过高亮之后空格也选那个词（词上屏后空格照样交给应用，
后面接着打下一个词），没动过的空格仍是原样上屏（`Session::navigated`，每轮查询清零）。测试者按直觉会拿空格选词，
这样既照顾直觉又不让 `kubectl` 这类词表没有的词被补全替换。Esc 清掉，退格删字母。英文模式不发云联想；回车原样上屏也不记「不纠这个串」。
组词中 Caps Lock 灭了先把字母原样上屏。配置 `[general] english_candidates = false` 关掉候选，回到纯直通；偏好设置里有勾选框。

**按应用关**：终端与代码编辑器里英文候选窗口会挡住应用自己的补全，vim / nano 里 Tab 和方向键又另有含义，所以 `[apps] english_candidates_off`
列出的应用（按 IMK 客户端的 `bundleIdentifier` 认，`*` 结尾按前缀匹配）里英文模式是纯直通。缺省名单是 Terminal / iTerm / Warp / Ghostty /
Alacritty / kitty / VS Code / Cursor / Zed / JetBrains 全家 / MacVim / Sublime / Xcode / Neovide；偏好设置「通用」页一个勾选框：勾上写缺省名单、
去掉写空表，改过名单的勾一下就回缺省。全局开关关着时这一项不起作用。开着详细日志时切到应用会把它的 bundle identifier 记进日志，往名单里加就照抄。
`[apps]` 分节以后按应用定 preedit 模式等也放这里。

**个人英文词表**（`user-english.tsv`，`词\t次数`）：随包词表只有两万多词，`gist`、`kubectl` 这类不在里面的词以前永远出不了候选。
现在原样上屏的字母串只要像英文词——纯字母、至少两个，中文模式下还要**切不成完整拼音**（`hao` 回车多半要的是字母本身，不学；
`gist` / `python` / `hello` 切不干净才是英文）——就记进个人词表，选中英文候选也记。英文候选由个人表 + 随包表一起出，
个人表在前：精确词取第一个有的，补全与纠正合在一起按选过的次数、词频排（`Engine::english_lists`、`english::suggest` 收词表列表）。
所以 `gist` 回车一次，下次敲 `gist` 它就是首选。

### 英文补全与 emoji

- **英文补全**：整段输入切成的拼音「不像话」（切不动、或非末尾有简拼 / 残缺音节：`compa` → `co'm'pa`、`impor` 连第一个字母都切不动）
  且至少 3 个字母时，除了整段正好是的英文词，还出词表里该前缀下最常用的 3 个（`compa` → company / companies / compared），
  紧跟在精确词之后、排在拼音候选前。干净的拼音（`xian`、`shan`）不补全，免得每个音节都冒英文。词频来自 wordfreq（`tools/corpus/english_frequency.py`）。
- **emoji**：前 5 个中文 / 英文候选里有配 emoji 的，emoji 紧跟在那个词后面（`ku` → 哭 😢 😭，`smile` → smile 🙂 😊），右侧标注对应的词；
  每个词最多 2 个、一次最多 3 个，`CandidateKind::Emoji`，上屏按那个词的音节消耗拼音（英文词带出的对应整段输入）、不记学习。
  数据是 Unicode CLDR 中文与英文 annotations（`assets/emoji/emoji-zh.tsv`、`emoji-en.tsv`，Unicode License v3，可发布，加载时合成一张表），
  `dict-convert emoji --language zh|en` 生成：单字词只收名字里含这个字的 emoji，名字里含这个词的靠前、名字越短越靠前。
  日文表要等有日语输入模式再说。

### 模糊音（默认全关，`config.toml` 的 `[fuzzy]`）

开了 z/zh 之后敲 `zi` 也出 知 / 之，开了 n/l 敲 `lan` 也出 南，开了 f/h 敲 `kaiha` 也出 开发；韵母 an/ang、en/eng、in/ing
只对完整音节生效（末尾没打完的音节本来就按前缀查，`fen` 自然出 feng 的字）。敲对的词仍然优先：模糊命中的词频减半参与排序，
同分排在后面。简拼位置也套声母规则（`zh` 前缀开了 z/zh 就按 `z` 查），整句转换用同一套写法。
CLI 用 `--fuzzy z-zh,n-l` 或 `--fuzzy all` 临时开。

### 双拼（默认关，`[general] shuangpin`）

四套方案：小鹤（`xiaohe`）、自然码（`ziranma`）、微软（`microsoft`）、搜狗（`sogou`）。键位表在 Core `shuangpin::table`，
按 Rime 的 `double_pinyin*.schema.yaml` 核对（搜狗来自 rime-ice 的整理），每套方案对全部音节做往返测试；微软与搜狗只差微软的 `v` 键兼作 üe。
开着时缓冲区里存的仍是敲的键，Engine 在切分前把键两两配对解成全拼（音节之间自动带 `'`，没有切分歧义），
之后查词、整句、云联想、学习全部走全拼那一套：拼音行显示解出来的全拼（`nihc` → `ni'hao`），学习按全拼记（`user-choices.tsv` 的键与全拼共用，切回全拼也受益），
上屏消耗按「候选盖住几个音节、每个音节几个键」换算回缓冲区（`kdfave` 选 开发 吃掉 4 个键，剩 `ve`）。
末尾落单的一键当声母 / 元音前缀出简拼候选（`kdf` → kai f…）；配不出音节的键起原样留作尾巴（`nibl` → `ni'bl`）。
零声母：小鹤 / 自然码写 `aa` `ai` `ah`（a、ai、ang）一族，微软 / 搜狗写 `o` + 韵母键（`oa` `ol` `oh`），双写元音的写法也认。
微软 / 搜狗的 `;` 是 ing：组句中末尾有落单声母时敲 `;` 进缓冲区（`x;` → xing），其他时候仍是标点，壳问 `Engine::takes_semicolon`。

双拼下 v / u / i 都是音节键，字母模式键让位（`ModeKeys::LETTERLESS`）：表达式与问字只能用 `?` 开头进。拼写纠错停用：敲错一键换掉的是整个声母 / 韵母，
全拼的一处编辑模型不适用。回车仍原样上屏敲的键；全部键都能解成完整音节的串（`nihc`）不记进个人英文词表，解不干净的（`gist`、`hello`）照记。
快捷候选（`rq` `sj` `xq`）与英文候选仍按敲的键认。
已知：`lue` / `nue` 与 `lve` / `nve` 同键，解成 v 的写法，词库里少量 `lue` 读音的词双拼下打不出（待把词库统一成 v）；`lo` 与 `luo` 同键，解成 luo。

### 快捷候选（搜狗 v 模式）

Core `shortcut` 模块，不查词库、由输入直接算出，`CandidateKind::Shortcut`，上屏吃掉整段作用域、不记学习：

- `rq` / `sj` / `xq`：今天的日期（`2026年9月3日`、`2026-09-03`、`2026/09/03`）、现在的时间（`19:06`、`19:06:23`、`19点06分`）、
  星期（`星期四`、`周四`），插在本地首选之后（首选仍是 日期 / 时间 / 需求 这类词库词）。
- 表达式键（缺省 `v`）开头进**表达式模式**：不解析拼音，preedit 原样显示。`v1+2` 出 `3` 与 `1+2=3`（支持 `+ - * x / ^`、括号、小数），
  `v123` 出中文数字小写 `一百二十三` 与大写 `壹佰贰拾叁`。此时**数字和运算符进算式而不是选词 / 翻页**，
  选第二项用上下键 + 空格；回车上屏原文；`v` 开头的英文词（`very`）仍走中英混输。表达式模式不发云联想。
- 问字键（缺省 `u`）后跟十六进制码点出那个字符：`u4e00` → 一，`u+1f600` → 😀（全是十六进制且含至少一个数字，或以 `+` 开头；
  `uface` 这种纯字母没有 `+` 当拼音问题）。本地直接答、不问云端。

模式键在 `[shortcut]` 分节配置，只能是 `v` / `u` / `i`（三个不能开头拼任何音节的字母，搜狗 / 微软同一思路：
一键进模式、不要修饰键、中文模式下零冲突）且互不相同，非法组合整个退回缺省。
没采用水杉的 Shift+字母模式键：macOS 上 Shift+字母是「临时打英文大写」，而且 Shift 单击留给以后切中英。

### 云联想（默认关闭，配置开启）

组句中停键 300 ms 后，云端给出的**词**（如 `zhangtao` 在财务上下文里的 账套，或纠错后的 `zhgdoima` → 这个东西吗）
补进候选窗口**第一页末尾**（`[predict] slots`，缺省 2：每页 9 个时就是 8、9 两格），前面带云朵，数字键照常选，
上屏吃掉整段拼音；本地首选仍在第一位，空格上屏的还是它。选中词库里没有的云端词，它会记成用户词，下次本地直接出。

请求里带：敲的字母、本地切分、光标前后文本（64 / 32 字）、本地整句转换的结果（`guess`）和本地前 5 个候选。后两样在提示词里明确标成
「本地的猜测，可能全错，只用来告诉你本地已经能给什么」，模型按字母与上下文独立判断、只给本地给不出或排错的词，没有就给空数组
（之前模型爱照抄本地第二个候选，`zhangtao` 回一个 张韬，等于没用）。

位置规则（Core `CandidateLayout`，壳只照着画）：云端词到了才补进第一页最后几格，原来那几格的本地候选挪到下一页；
前面的本地候选**一格不挪**——之前云端词插在第二位，用户看着 2 号按下去的瞬间被顶掉、选错，这是改的原因。**不预留、不画占位**：
没到、没词、超时都什么都不变，页面上只会「多出几个词」这一种变化（预留槽位加灰色占位的做法试过，云端常常空手而归，
占位出现又消失反而闹眼睛）。用户已经翻到后面的页、或高亮已经移到末尾会被挪走的那几格时，到的词丢掉不补。
云端词比格数多只取前几条；与本地候选同文的不要（本地已经能给）；云端词只在第一页，翻页后全是本地候选。`slots = 0` 不要云端词、只要整句补全。
问字模式没有本地候选，答案从第 1 格起排满一页。

### 问字模式（云联想的一部分，问字键 `u` 或 `?` 开头）

缓冲区为空时敲问字键（缺省 `u`）或 `?` 进问字模式，接着用拼音敲问题：`usangemushishenmezi`（三个木是什么字）、`umumumu`（报部件）、
`ufaguoshoudu`（短事实问答）。`?` 在任何配置下都是别名，也是英文模式（Caps Lock）下唯一的入口（`u` 在英文模式里就是字母 u）。
本地不出候选，preedit 显示 `usan'ge'mu…`，停键后云端答字或短答案，
带云朵与带声调读音（森 sēn），数字键选中上屏、吃掉整段。答案不做拼音校验（它本来就对不上问题的拼音）。
请求里除了字母与切分还带 `question`：本地整句转换把问题拼音转成的汉字（`PredictionRequest::guess`，可能错字），模型据此理解问题；
提示词强调用户是打不出这个字才来问的，**只答被问的字、不复述问题**。模型仍把问题整句写回来时（`?sangezhishishenmezi` 曾答 三个直是什么字），
Core 按 `prediction::restates_question` 剔掉：与本地转出的问题相同、包含它的后半截、问题不短而答案一样长、或答案里带疑问词。
中英文模式（Caps Lock）都能进：`?` 后面紧跟的不是字母（回车、空格、标点、方向键）就还原成问号上屏
（中文模式全角 `？`、英文模式半角 `?`）。回车和空格只做「把这个问号上屏」、键本身吞掉（否则聊天框里回车会连消息一起发出去、
空格会多一个空格），标点和方向键还原后再交给应用；退格 / Esc 清掉。英文模式下 Caps Lock 送来的大写字母按小写收进问题。
没开云联想时 `?` 仍然进问字模式但等不到答案，回车上屏原文；离线拆字版（IDS 数据）待做。
同一次请求还给一条「☁ 整句」，画在 preedit 右侧：它是以这个词开头的完整说法（`suoyiwoxiangq` → 所以我想去吃饭），
替换整段拼音，Tab 接受，继续敲键就换掉。有应用上下文时整句接着上下文写；没有也给最常见的说法。
接受的整句没有拼音，记不了词频与用户词，但会按语言模型切成词（Core `sentence::segment_text`：文本子串上的 Viterbi，模型认识的子串才算词，
标点处断句）逐条记进个人 n-gram，与选整句候选一样；整句退格删光、同一段拼音重选时这些转移一并退回。没接语言模型时不记。
上屏之后不联想。

答案怎么进候选：问字没有本地候选，`CandidateLayout::capacity` 把整页都给云端；壳补云端词前的「别挪走用户正看着的候选」保护
（不在第一页、或高亮落在末尾云端格上就不补）对没有本地候选的情况必须放行，否则 `page_size - capacity = 0` 会把所有答案丢掉
（2026-09-07 修过，`host::cloud_slots_untouched`）。联想线程的缓存不存空回复，否则第一次没答上来的问题重打也永远是空。

云联想的条目用云朵图标和不同颜色区分，永远只是本地候选之外的补充：本地候选的位置与顺序都不因它变。
菜单栏「中 / 英」后带 ☁︎ 表示联想开着、上下文会发往云端；Secure Input 里绝不发送。

### 中英切换（两个系统的习惯不同）

| 系统 | 切中英 | 英文模式 |
|---|---|---|
| macOS | Caps Lock 位置的中/英键。系统层面它切的是 Caps Lock 状态，我们把「Caps Lock 亮着」当作英文模式 | 默认小写，按住 Shift 大写；标点不转全角。macOS 上 Caps Lock 亮着时按不按 Shift 送来的都是大写，所以按键时读一次 Shift 的硬件状态（`NSEvent.modifierFlags`）决定大小写 |
| Windows（Phase 5） | Shift 单击切中英；Caps Lock 是真正的大小写锁定 | 默认小写，按住 Shift 大写 |

macOS 上如果系统开了「使用大写锁定键切换 ABC 输入法」，按键会直接切到 ABC 输入源，我们收到 deactivate、
收窗即可，两条路都能得到小写英文。

中文标点：`, . ? ! : ; ( ) [ ] < > \ ^ _ $ ~` 转全角，`"` `'` 成对切换；数字后的 `.` 保持半角。
`-` `=` 不转换。

### 拼音行（preedit）

候选窗口顶部有一行 preedit：带 `'` 的切分拼音和我们自己画的光标。marked text 里的插入点由应用决定画不画，
终端和不少 Electron 应用不画，所以光标必须自己画。
Core 给的是分段（`Query::marked_segments`，`MarkedKind`：敲的拼音 / 光标后剩下的拼音 / 被纠错改掉的字母），
壳按段选样式（剩余部分画淡，纠错改掉的画淡加删除线），光标位置按拼接后的字符数算。

### 拼写纠错

拼音「不像话」时（切不干净有尾巴，或非末尾的音节里有简拼 / 残缺）试一处编辑：相邻换位、换一个字母、多一个、少一个；
末尾是单字母时（`mingtai'n`，可能是合法简拼也可能是敲反了）只试相邻换位。只保留改完后每个音节都完整的变体，
再按噪声信道挑：每个变体跑一次整句转换，得分最高的那个还要**扣掉一次编辑的代价（`CORRECTION_PENALTY`，5 nat）后仍高于原串按原样转出的得分**才纠
（`nihooma` → 你好吗，`woxiagnqu` → 我想去，`mingtain` → 明天，`nihaov` → 你好；原串切不干净就没有原样得分，能转出整句的纠正直接胜出）。
合法简拼（`nhao`、`womend`）原样与纠正后走的是同一条路径，扣掉代价就输了，不会被误纠；
整段本身是英文词的不纠（`hello` 不会变成 和咯）；「删掉刚敲的最后一个字母」不算纠正（`kaiv` 的 v 留作尾巴）；少于 4 个或多于 24 个字母不纠。
2026-09-05 之前的规则是「纠正后至少凑出一个两音节词」，语言模型把 你/好/吗、我/想/去 都切成单字路径，这条规则反而放行了 你/后妈、我/峡谷/区，已废。

**词图里的敲错边**（2026-09-06）：上面那路只管切不干净的输入；全部音节都合法、整句却说不通的（`meiganxi` 没敢洗）另有一路——
整句词图里每个完整音节除了敲的原样，还按它的一处敲错变体（相邻两键换位 `shou`→`shuo`、敲到相邻键 `ni`→`mi`、多一键 `gang`→`gan`、少一键 `gan`→`guan`；
`correction::typo`，只算合法音节，不算不相邻的键）查词，命中的词扣那类敲错的代价（换位 / 相邻键 5 nat，多键 / 少键 5.5，`TypoKind::cost`）。
Viterbi 按噪声信道挑路径：`meiganxi` 读成 没关系 只扣一次 5.5，仍高于 没/敢/洗 三个单字，就出 没关系；`meiganxie` 没感谢 原样说得通，不动。
词级候选**不**带敲错变体（`kaif` 会冒出 咖啡 挤掉更长的原样词），整句路径读出的一个词（没关系）作为词候选插到最前；
词级候选里有音节正好拼成整段输入的词时不许敲错边压过它（`jineng` 按 `jin'eng` 切时词图里读出 近藤，但 技能 正好拼成 `jineng`，退回原样路径）。
不到 4 个字母、双拼、非末尾带简拼的切分、整段一处编辑已生效的纠正后拼音都不加敲错边。
上屏时候选音节逐个对回敲的字母（`Engine::align`：原样、没打完、模糊音或敲错变体、公共前缀），按敲的字母消耗，
靠敲错变体对上的 (敲的, 要的) 音节对记进**个人敲错表**（`user-typos.tsv`，`Learner::record_typo`），退格重选时退回；
接受整段一处编辑的纠正也记（编辑落在的那个音节，`Correction::typo_pair`）。以后那条边的代价按 min(ln(1 + 次数), 3) 打折，
整段纠错的编辑代价同样打折——习惯性把 `shuo` 敲成 `shou` 的人，几次之后 我说 就自然排上来。这就是「个人按键混淆模型」，不训练、在线计数。

纠正生效时候选全部来自纠正后的拼音，拼音行把被改掉的原字母画成删除线插在原位：`ni'h` ~~o~~ `ao'ma`；
选词按纠正后的音节消耗拼音，再按那处编辑换算回原串（多敲的字母跟着被吃掉）。**回车仍原样上屏** `nihooma`。
学习：选了纠正后的词按原输入串记选择（`user-choices.tsv`），下次同样敲错直接首选；回车原样上屏过的串记成 `<raw>`，以后不再纠它。
Core `correction` 模块只产生候选纠正，挑选与学习在 Engine 里。

**输入日志**（`[general] input_log`，缺省开）：每次上屏往数据目录的 `input-log.jsonl` 追加一行——`keys`（消耗掉的原始键）、`pinyin`（整段切分，纠错时是纠正后的）、
`corrected`、`text`、`source`（word / cloud / sentence / english / shortcut / emoji / raw / translation / cloud_sentence）、`index`（选的是查询时候选列表里第几个，
晚到的云端词与原样上屏为空）、`top`（查询时前 5 个候选）、`scheme`、`english`、`t`（本机时间）；退格撤销另记一行 `retract`，指回被撤销那条的 `id`。
只有敲的键与上屏的文字，不含应用里的上下文；只写本机，「高级」页可关可清，「关于」页隐私说明有写。用途：离线回放算首选命中率做排序 / 整句的回归评测，
以及个人模型（Phase 7）的训练对。回放工具是 CLI `--replay`（见 CLAUDE.md），首批 150 条：词首选 75%、前五 95%，整句首选 86%。Core `Engine` 在 `query` 时留摘要（`QuerySnapshot`）、上屏时凑成 `InputLogEntry` 交给 `InputLogger`（学习 crate 的 `InputLog` 落盘，攒 20 条刷一次，停用输入法时也刷）。

选错了词也有补救：上屏后马上把它整个退格删掉、重打同一段拼音换选别的词，上一次记的学习（选择次数、输入串选择、词转移）会退回去，
不用担心一次误按空格把错词教给输入法。

拼音显示在哪由 `[general] preedit` 定：`both`（缺省）行内 marked text 与窗口顶部都显示；`inline` 只在行内，窗口不带拼音行
（云联想的整句补全仍在窗口顶部单独一行）；`window` 只在窗口，应用里放空的 marked text——终端与部分 Electron 应用行内拼音画得难看时用，
光标矩形仍从应用的插入点取。

组句期间其余编辑动作一律吞掉，否则应用会动光标、丢 marked text。
