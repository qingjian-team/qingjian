# 0001 显示面自绘，不接现成 GUI 框架

- 状态：已采纳
- 日期：2026-09-13（结论成形于 `docs/design/rendering.md` 的调研，本文件 2026-11-28 追记）
- 相关：[../rendering.md](../rendering.md)、[../candidate-ui.md](../candidate-ui.md)、`crates/bamboo-slip`、
  `crates/qingjian-render`、`apps/settings`

## 背景

候选窗与设置程序都要在三个平台上长得一样、动得一样：主题两套（浅 / 深）、每屏 10 个候选、带词性 + 译文的
两行排版、动画、DPI 跟随、以及「候选窗必须在 `WM_MOUSEMOVE` 之后的那一帧里出现在正确位置」这类延迟预算。
输入法候选窗还额外要求在 UIAccess 进程里画（见 [0002](0002-windows-two-processes.md)），并且不能因为壳不同
就换一套视觉语言。

## 备选

**A. WebView（Electron / Tauri / WKWebView）**：布局快、主题容易做。否掉的原因是冷启动与内存——候选窗是
每次按键都要用的东西，多一个 WebView 运行时意味着每个宿主进程或每个 Server 进程多几十 MB 与一段不可控的
首帧延迟；且 Windows 侧 TSF DLL 会被加载进每个应用进程，带一个 WebView 运行时不现实。

**B. 平台原生控件（WinUI / AppKit / GTK）+ 三份实现**：与系统观感一致，无障碍免费。否掉的原因是三份实现
必然漂移——候选窗的排版、圆角、阴影、翻页高亮在三套控件里对不齐，改一个视觉细节要改三次，且 macOS 与
Windows 各自的动画曲率不同，做不到「同一套主题」。

**C. 现成 Rust GUI 框架（egui / slint / iced）**：省事，社区维护。当时的直接否决点：
1. 三者都以「窗口 + 立即模式重绘」为中心，而候选窗要的是「渲染成一张位图交给系统贴」——
   Windows 上是分层窗 `UpdateLayeredWindow`、macOS 上是 `NSImage`、Linux 上是给框架交 pixmap，
   都要绕过框架自己的窗口与事件循环；
2. 主题需要精确到「同一份主题定义推出两套配色 + 圆角 + 阴影 + 字族回退」，框架的样式系统要么不够、
   要么只能 fork；
3. 输入法的排版有特殊约束（候选两行、拼音行与候选基线对齐、按候选宽度自适应窗口宽度），
   在框架的布局系统里都要写自定义测量，省不下什么。

**D. 自研最小渲染管线**：布局 + 文字 + 场景树 + 贴图自己写，底下的光栅化与排版交给成熟库
（tiny-skia 光栅、cosmic-text 排版与字族回退）。代价是要自己养一个 UI 引擎。

## 决定

走 **D**：`crates/bamboo-slip` 提供场景树、布局、文字、动画、控件与窗口宿主，产出位图；
`crates/qingjian-render` 只负责「帧数据 + 主题 → 场景树」，各平台的壳只做「贴位图 + 转事件」。
设置程序、青简剪贴板、候选窗、状态条共用这一套。

## 后果

好的：

- 三个平台的候选窗**像素级同源**：主题、排版、动画只写一份，改一次三处一起变
- 渲染与平台解耦：Linux 面板、Android 候选条都复用同一份场景树输出
- 延迟可控：一次候选页的绘制在毫秒量级（`docs/notes/performance.md` 有数字），没有运行时冷启动

坏的 / 必须一直守住的：

- **`bamboo-slip` 里不许出现青简的业务概念**（词库、候选、输入法协议），它只是 UI 引擎；
  `qingjian-render` 才是「知道候选长什么样」的那一层。这条由 `tools/ci/layers.py` 断言，
  违反会让 UI 引擎无法被别的项目复用，也会把业务改动传导到整个引擎
- 自研引擎自带维护成本：字体回退、DPI、无障碍、输入焦点这些别人替我们踩过的坑要自己踩。
  现在 `bamboo-slip` 约 1.7 万行、66 个测试，是全仓第二大 crate
- 无障碍（读屏）不能免费获得：候选文字要走系统可访问性接口单独报，不能指望控件自己做

## 复审触发条件

- 第二个移动平台（iOS / HarmonyOS）要在 Rust 侧统一屏幕键盘时，重新评估布局与命中测试的表达力
- 出现「框架已经能直接贴位图、且主题系统够用」的成熟选项时（即备选 C 的那三条否决点不再成立）
- `bamboo-slip` 的维护成本连续两个季度超过「三份原生实现」的估算时
