# 九宫格拼音

手机上的 9 键拼音：`2`–`9` 每键三四个字母，`64426` → 你好。它是一种输入方案（`Engine::set_nine_key`），和双拼、注音一样是设置项，
不是模式；歧义消解、排序、整句、学习全在 Core，壳只有一张键位表和一列「选拼音」。

## 为什么能复用全拼的管线

- **每个位置多种写法本来就有。** 词库的 `lookup_pattern_alt` / `lookup_exact_alt_step` 与整句词图 `sentence::convert_lattice`
  的入参都是每位置若干 `SyllablePattern`——模糊音与敲错变体也是这套接口。九宫格的一个位置 = 同一段数字码下的全部音节
  （`64` → `ni` `mi`），代价都是 0，由词频与语言模型在词和路径上分辨。
- **一个字母一个数字。** 任何一种读法与数字串等长、逐字符对齐，所以候选消耗多少输入直接按它的音节长度算，不需要对齐搜索；
  `'`（壳的分词键）照旧跳过。

## 切分与字节偏移音节 DAG

`nine_key::lattice(input)` 在输入串的字节偏移 `0..=end` 上构造一张音节 DAG（`Lattice`），保留**全部**合法边界，不再按纯结构排序截成少数形状：

- 一段输入是合法边，当且仅当它是某个完整音节的码（或已选定字母 / 叹词读法），或在末尾 / 简拼时是某个音节前缀或声母的码；边指向跳过紧跟 `'` 后的下一个字节偏移。
- 若存在不依赖中间未选定单码简拼即可走到 `end` 的完整路径（`has_complete_path()`），先裁掉中间未选定的单码简拼边，再做后向可达剪枝；既防止长句把四码完整音节误拆成「单码声母 + 三码音节」（如 `7468` `shou` 误拆成 `s + hou`），又压低 DAG 分支因子。纯简拼串（如 `57`）无完整路径，保留全部简拼边。
- `Lattice::best_shape()` 用一次线性 DP 算出结构最优单条形状（音节少 > 不完整少 > 前面音节长），供拼音列起点、叹词判断、未选定偏好和拼音行兜底用。

缓冲区里可以混着字母：用户在拼音列里点了 `ni`，壳调 `Engine::pin_nine_key("ni")`，第一个还没定的位置的数字换成字母并接一个 `'`
（`64426` → `ni'426`）。字母位置只有它自己一种写法。选定只发生在第一个没定的位置，所以定下的总是缓冲区开头连着的全字母段，
`Engine::nine_key_pinned` 按这个数出拼音行上要画下划线的字数（壳另加前面留着的词）。退格先撤留着的词（`undo_selection`），
末尾是定下的音节时整个换回数字（`unpin_nine_key`：`ni'hao` → `ni'426`，可以重选），否则删一个键，删完选定音节后面的键时它后面自动接的 `'` 一起去掉；
换回数字后记下用户选过的写法（`nine_key_unpinned`），之后只删键时读成这个写法的候选挪到前面（`prefer_unpinned`，拼音行跟着首选），`64` 不会从 ni 变回默认的 mi；打了新键就不再偏向。选定与退回都留着前面选好还没上屏的词。

## 查询（`Engine::query_nine_key`）

与形码一样是一条平行管线，在 `query_inner` 里进切分之前分岔：

1. **词级查词（`score_lattice`）**：沿 `Lattice` 从起点 0 做词库前缀存在性剪枝（`Dictionary::lookup_exact_alt_step` 的 `has_longer`）的深度搜索——到达 `end` 的路径走 `lookup_all`（含末尾前缀补全），中间前缀走 `lookup_exact_all_step`（逐词上屏用）；覆盖全部合法切法且不重复查共享前缀，与全拼共用同一个 `ranking::rank` 和打分闭包。
2. **整句转换（`convert_nine_key` → `sentence::convert_lattice`）**：直接把 `Lattice` 喂给统一字节偏移 DAG Viterbi，只跑**一次**动态规划，借助 `SpanCache::get_or_insert_step` 缓存格子候选与 `has_longer` 剪枝。
   - 末尾位置若本身已是完整音节（如 `7426` → `piao / qian / shan`），整句按精确完整音节查，避免借末尾前缀展开成更长音节（如 `退票` 误出 `腿上`、`收藏里` 误出 `收藏夹`）；词级查词仍保留末尾前缀，保证半截输入的补全候选照常出现。
   - 完整音节格按同码读法组合数等比放大候选名额（1/2/3+ 倍，基准取 `search_limits.span_candidates`），DAG 束宽至少 16，避免多音节同码（如 `7426` 含 5 种音节）把次高频音节挤出词图。
   - 规则同全拼：至少两个音节、路径不止一个词、没有占位音节。
3. **显示**：`Query::typed_display` 沿 `Lattice` 把首选候选的音节逐段对齐回输入（`ni'hao`、`lü'guan`），即使首选来自任意非首结构切法也能准确对齐；首选只覆盖前面一段时剩余部分按 `Lattice::suffix_positions` 补齐；`decoded_keys = true`。
4. **拼音列**：`Query::pinyin_choices` 从第一个还没选定成字母的位置（`!Position::pinned`，即使该段数字只有一种完整读法如 `584` → `kui` 也不跳过）起，枚举所有长度能读成的完整音节、叹词读法（`nine_key::INTERJECTIONS`：ng / hm / hng → 嗯 / 噷 / 哼）与一码的单个字母（`nine_key::spellings_from`）。完整音节与叹词在前、单字母兜底在后，档内按「在当前候选里出现最靠前的位次 → 该音节在用户习惯与词库里的最高权重 → 长度」排序，不再按最长结构切法硬钉顶部。选了比当前位置短的音节后，`pin_nine_key` 在它后面接 `'`，剩下的数字重新切。`n` / `m` 仍是简拼声母，整段只有这一个字母时才多给 嗯 / 呣。

不走的：拼写纠错、模糊音、英文尾段、表达式 / 问字模式、辅码（数字键都被占了，这些以后按需再接）。

## 上屏与学习

`consumed_by` 在九宫格下按候选音节长度逐个消耗（跳过 `'`，不超过作用域）；按输入串记的选择用**候选自己的拼音**当键
（`nihao`），和全拼共用一份学习数据，换键盘不丢。个人敲错表不记（数字对不上字母）。整句上屏时的词序列重算走同一套 `Lattice` 统一整句转换。

## 壳

键位：`1` 分词（`'`）、`2`–`9` 字母；左侧一列是 `pinyin_choices`，点了就 pin，不在组句时放标点；右列退格、重输、`0`。英文模式下九宫格退回全键盘。
Android 的实现见 `docs/notes/android.md`。

## 验证与评测

- 单句与逐键耗时：`cargo run -p qingjian-cli -- --nine-key --typing 9663694747852432`
- 冻结语料批量评测：`qingjian-cli --nine-key --eval-text <frozen.tsv>` 会自动把全拼列映射到九宫格数字键序列，直接复用全拼冻结集（`bench_words234` / `zhihu120` / `social_devnc`）输出首选率、字准确率与耗时，历史基线和前后对照见仓库外 `benchmark-log.md`。
