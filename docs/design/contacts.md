# 通讯录里的名字（#876）

Android 上可以把系统通讯录里的名字并进候选：打名字的全拼、简拼、双拼或九宫格，通讯录里的人出现在第一页、带人头标记；上屏名字后，候选条接着给出这个人的电话、邮箱。
这一页写清楚它的边界：在哪里做、怎么排、读音怎么来、隐私边界在哪里。

## 分工

| 部分 | 位置 | 做什么 |
|---|---|---|
| 读通讯录 | Kotlin `contacts/ContactsSync` | 设置开着、有权限时在后台线程读名字、电话、邮箱，整份 JSON 交给会话；通讯录变了（`ContentObserver`）重读 |
| 名字词库 | Core `contacts/`（`ContactBook`） | 名字 → 读音的小词库，加每个名字的电话、邮箱；同名的合在一起 |
| 查词与排序 | Core `engine/contacts.rs` | 名字词库并进查词；整段对得上的名字挪进第一页 |
| 上屏后的电话、邮箱 | Android 会话 `session/contacts.rs` | 上屏名字后把电话、邮箱放进补全（与邮箱后缀、算式结果同一条通道），光标前不再是这个名字就收起 |
| 人头标记 | Kotlin `CandidateStrip` | 在名字候选的右上角画人头 |

人头由壳画、不写进主题：内置主题有九个，社区主题也不会有这个绑定，壳画一次所有主题都有，与补画 emoji 同一种做法。
桌面端没有通讯录，Core 的接口（`Engine::set_contacts`、`is_contact`、`contact_details`）与平台无关，以后别的平台要接也是交同样的联系人列表。

## 收什么名字

- 去掉空白后 2–6 个汉字的名字。英文名、单字（「妈」）、带符号或更长的备注（「王师傅 修空调电话」）不收：英文名与英文词表冲突，单字会挤进大量单字查询，长备注多半不是在打名字。
- 一个名字最多带 6 条内容（电话在前、邮箱在后），候选条一屏放得下。
- 同名的联系人合成一个名字，内容合并去重。

## 读音

名字的读音按这个顺序定，有字读不出来的名字跳过：

1. 开头是多音字的姓（曾、单、解、区、仇、朴、尉迟、万俟……，表在 `contacts/surname.rs`），这个字按姓读。
2. 整个名字是词库里的词（「爸爸」「长辈」这类备注名），用词库的读音；与按姓读的不一样时两条都收。
3. 否则逐字取单字表（`data/tones.tsv`）里最常见的读音；单字表里没有的生僻字取主词库里这个字词频最高的读音。

只收一两条读音，不做多音字的笛卡尔积：名字多半只有一种读法，组合多了反而让别的输入撞上这个名字。

## 排序

名字在词库里的词频很低，只够进整句词图，不靠词频排。查完候选后，第一个整段对得上（上屏能吃掉全部输入）的名字挪到第二位，第一位留给原本的首选：
简拼 `zw` 这类输入撞的词很多，名字不压过最常用的词，但一定在第一页。名字本来就排在前两位的不动；与词库里的词重名时只出现一次（同一个候选），只是多了人头。

## 上屏后的电话、邮箱

- 单独一个开关（缺省开）：号码显示在候选条上，录屏、投屏或旁边有人时会被看到，有人只想要名字。
- 只显示、不自动上屏：点了才上屏，原样上屏（电话已去掉空格与横线），名字与号码之间不加东西。
- 什么时候收起：接着打字、按空格或别的键、光标前不再以这个名字结尾（会话在壳问补全时检查）；删除键、重输键的第一下只收起它们，不删已经上屏的字（`Session::has_offer`），删除键上划清空后的「撤销」同样处理。
- 不改按键的含义：空格、回车照常是空格、回车，不会上屏号码。

这条「上屏后在候选条上接着给东西」的通道以后也给上屏后联想（#861）用。

## 隐私

- 缺省关；在「设置 → 词库 → 通讯录」打开时才申请读通讯录的权限，没给就保持关着。
- 名字与号码只在输入法进程的内存里，不落盘；关掉开关时整份清掉。
- 上屏名字不记学习（词频、选择、词与词的搭配）、不写输入日志；输入日志记的「看到的候选」里也去掉名字。
- 云联想请求里的本地候选与本地整句里有名字时去掉（候选删掉那一条，整句整条不发）。应用给的光标前后文是应用里已有的文字，照旧按云联想的规则发。
- 只给了「仅在使用中允许」时，有的系统（MIUI）在输入法服务于后台启动时给空结果：读到零个时不当成读过，每次键盘弹出再读，两次至少隔一秒。
