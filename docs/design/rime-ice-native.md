# 原生引擎的雾凇全拼适配

使用青简已有的 Rust Engine 处理全拼，读取用户提供的雾凇数据。中文词库进入原生查询、整句与学习流程；日期、计算器等扩展由 Rust 生成候选，通过同一套上屏接口提交。

```text
用户雾凇目录 → 导入中文词库、读取英文与扩展数据
按键 → 青简 Engine → 拼音查询 / 特殊输入 → 候选 → 青简上屏与学习
```

当前只适配全拼。双拼、注音和形码继续使用青简原有实现。切换、选词、翻页和译词快捷键沿用青简；不读取 Rime 的 `key_binder`、`ascii_composer`、`editor` 配置。

## 数据边界

`Engine::load_rime_ice(source, cache)` 加载完整目录快照，成功后才替换当前数据。启用时，雾凇中文词库成为主查询词库，用户词与附加词库继续参与查询。关闭后恢复青简主词库。

- `rime_ice.dict.yaml` 与递归 `import_tables`：合并中文分表，支持无注音腾讯词表的补音。原有导入入口也可单独使用。
- `en_dicts/en.dict.yaml`、`en_ext.dict.yaml`、`cn_en.txt`：英文候选、补全与中英词条。
- `custom_phrase.txt`、`symbols_v.yaml`、`radical_pinyin.dict.yaml`、`opencc/emoji.txt`：短语、符号、拆字与 Emoji。
- `rime_ice.schema.yaml`：读取日期触发词、农历模板、UUID 触发词、置顶词、长词提升和英文降序设置。
- `lua/corrector.lua`：仅提取字面字符串表中的输入码、词与读音提示。

不运行 Lua，也不解释 Rime 配置的任意补丁或拼写代数。修改源目录后重启青简；同一路径的配置刷新复用快照。中文缓存按主表与 `cn_dicts/` 文件内容区分，源文件只读。第三方词库、Lua 文件与转换缓存均不随青简分发。

## 输入行为

原生切分支持全拼、简拼与混合输入，词库读音规范化支持 `nue/nve`、`lue/lve`。适配层补充 `qv/qu` 等 j/q/x/y 的 u/v 写法及 `hzi/zih` 等 zh/ch/sh 换位，青简原有纠错继续工作。

日期输入码为 `rq`、`sj`、`xq`、`dt`、`ts`、`rqzh`、`rqen`；农历为 `nl`、`NYYYYMMDD`。农历由 `lunar_rust` 计算，限制在 1900–2100 年，不加载 Rime 的二进制反查库。已对照闰二月、2033 年闰十一月和 2051 年日期样例；尚未逐日对照整段年份。

`cC` 计算器支持四则、幂、括号、百分数、阶乘及雾凇内置数学函数；`R` 生成四种数字、金额写法，金额小数保留角、分、厘、毫。算式限制 512 字节、32 层递归、64 个参数，拒绝任意代码。浮点显示采用 Rust 格式，例如整数结果显示 `3`，雾凇 Lua 可显示 `3.0`。

`U` 输出可显示的 Unicode 码点；`v` 查询符号；`uU` 用部件拼音反查汉字，全拼后的反引号追加部件筛选。UUID 在同一段输入刷新时保持不变，并随输入上下文保存。Emoji 和繁体转换沿用青简候选与转换接口。

## 兼容范围

目标是提供雾凇全拼的这些输入入口与候选内容。普通词序、整句、英文补全、长词提升与学习仍基于青简算法，不保证与 Rime 的候选逐项同序；Rime 自定义 Lua、任意 YAML 补丁与自定义拼写规则不会自动生效。

各平台仅装配配置并转发输入。新增大写前缀、数字和运算符转发需要各平台真机验证；Core 与 Server 测试不能代替 IMK、TSF、Fcitx5 桌面验证。
