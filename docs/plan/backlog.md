# 任务池

2026-11-23 建。按主题分号，编号稳定，`docs/plan/input-methods.md` 里引用的编号都指这里。已完成的不移走，就地标 `[x]` 留追溯；新任务往后加号，不复用旧号。

## A 输入能力

- [ ] **A1 V 模式类的转换**：数字转中文（`123` → 一百二十三）、日期/时间格式、大小写与全半角、金额大写。搜狗/微软都有，青简目前只有 `rq`/`sj` 两个快捷码。验收：命令行与三个桌面壳都能用，候选里直接给结果。
- [ ] **A2 Android 撤销上屏**：三个桌面壳已有退格撤销（`note_backspace`），Android 的 `InputConnection` 还没有。验收：误上屏后一次退格能整段撤回。
- [ ] **A3 常用语分组与占位符**：自定义短语按「工作/地址/账号」分组，支持 `{date}`、`{clip}` 这类占位符；设置页可拖拽排序。搜狗、微信键盘都有分组。
- [ ] **A4 标点细节预设**：中文状态下轻按 `/` 上屏 `、`、长按给 `/`；`~` 给 `～`。做成可开关的预设，不写死。
- [ ] **A5 Linux 接辅码**：`custom-schemes.md` 写明辅码仅 macOS/Windows；Linux 的 Server 已有码表装配，缺 `;` 分流与候选挂码。验收：Linux 上 `;` + 码表能筛候选，和 macOS 行为一致。
- [ ] **A6 模糊音逐对开关**：现在十条规则一起开。改成 z/zh、c/ch、s/sh、n/l、f/h、r/l、an/ang、en/eng、in/ing、ian/iang 逐对可关，默认全开。Fcitx5 就是逐对勾选。
- [ ] **A7 右键置顶即存词**：候选上右键「置顶」直接把该词写进用户词库并给最高权重。Rime/Fcitx5 都有类似行为；青简现在要去设置里加短语。
- [ ] **A8 手写补字**：鼠标/触控在候选窗上写一个字，按笔顺或整字识别后插入候选。优先 macOS/Windows 触控板；Android 用系统手写 API。工作量按「只做单字、不做连写」估。
- [ ] **A9 同句多语言自动判语言**：现在中/英/越是手动切输入法。目标：同一段缓冲里 `nihaohello` 这类能自动分段，各自用对应词库与模型；判错时一次 Tab 纠正。Gboard/SwiftKey 的核心卖点。
- [ ] **A10 滑行输入（Android）**：九宫格/全键盘上按住滑过字母路径，按轨迹与词库打分出候选。先做全键盘、英文 + 拼音首版；用 `androidx.input` 的手势回调，不自己造触摸识别。
- [ ] **A11 语音输入补齐平台**：`qingjian-voice` 已有，macOS 接了；Windows/Linux 的入口与权限还没接。验收：三平台都能按住说话、上屏带标点。
- [ ] **A12 表情/贴纸/GIF 面板**：emoji 面板已有（9587 条）；补「最近使用」「组合 emoji」「贴纸包」三类。GIF 需要联网，按 `[predict]` 的开关一起关。

## B 词库与领域包

- [ ] **B1 领域词库包**：按搜狗专业模式的 13 个领域做可选包，独立候选来源、独立排序权重、带领域内符号与缩写关联（`偏导`→`∂`、`DMSO`→`二甲基亚砜`）。音乐领域先做（用户是音乐教师，`d大调`、`f小调`、`降b` 这些现在要拆字打）。
- [ ] **B2 细胞词库订阅与导入导出**：`dicts/` 目录下放 `.qj` 包，设置页按「学科/行业/游戏」勾选启用；支持导出一个包的词条为 TSV。
- [ ] **B3 默认词库扩量**：现在产品词库 8.7 万条，日常命中率低于搜狗/微软。目标 30 万条起步（常用词 + 人名地名 + 网络热词），随包体积控制在 +8 MB 内。
- [ ] **B4 精校词库**：参照雾凇拼音的路子，给 qingjian-dicts 建一套「长期维护 + 逐条校对」的词表，带来源与许可说明。验收：抽 500 条人工过一遍，错词率 < 1%。
- [ ] **B5 导入搜狗细胞词库（`.scel`）**：解析 `.scel` 的二进制格式，转成 `.qj`。Fcitx5 已做，格式资料公开。先做只读导入，不做反向导出。
- [ ] **B6 词库热更新**：不重启输入法，检测 `dicts/` 下新增/改动的包后重建索引并切换。现有 `reload` 只重读配置。
- [ ] **B7 游戏术语词库（三角洲行动等）**：待确认「三角洲库」的具体位置与格式（本地目录/仓库/导出的表）。确认后做成独立领域包：地图名、干员、枪械、弹药、改枪术语，带简拼与英文缩写（`m4a1`、`ak12`、`vss`）。验收：这些词在简拼下能一次出，且不挤占日常词。

## C 模型与智能

- [ ] **C1 云候选（不只云联想）**：现在云只补整句。加一路「云拼音候选」：把当前拼音串发出去，取前 3 条混进候选，带缓存与最小长度门槛（Fcitx5 的做法：最小拼音长度、可选后端、可关）。默认关。
- [ ] **C2 语音模型平台化**：`qingjian-voice` 的模型与后端在 macOS 外还没接；补齐 Windows/Linux，模型按需下载。
- [ ] **C3 代码模型**：`qingjian-code` 已有（代码标识符识别），补「驼峰/下划线/缩写」三种写法互转的候选。
- [ ] **C4 个性化微调**：`docs/notes/neural-rescoring.md` 的下一步「闲时训练」——用本地输入日志在空闲时做轻量微调/LoRA，模型只在本机。需要先解决日志脱敏与训练成本。
- [ ] **C5 模型量化到 Q4 线性层**：Q8 已上；Q4_K 能把线性层再省一半，但要用回放集与 `--eval-text` 逐条对账首选。验收：整句首选掉不超过 0.5 个点。
- [ ] **C6 模型闲置卸载的界面开关**：`[model] idle_unload_seconds` 已有（默认 300，0 关闭），但只在配置文件里。设置页「实验功能」加「闲置后释放模型」开关 + 秒数选择（5 分钟/15 分钟/1 小时/不释放）。验收：开关改完立即生效，不必重启。
- [ ] **C7 模型加载进度可见**：首次加载知意要十几秒（Metal 编译），现在只有日志。候选窗/状态条给一个「模型准备中」的细条。
- [ ] **C8 剪贴板智能**：`qingjian-clipboard` 已有历史；加「按类型分组（链接/代码/图片）」与「粘贴前预览」。

## D 性能与内存

- [ ] **D1 常驻内存账本**：Server 启动与每次 reload 后记一条 RSS（Windows `GetProcessMemoryInfo`、Linux `/proc/self/statm`、macOS `task_info`），日志里能看「词库 / 模型 / 渲染」各占多少。没有账本就没法持续降。
- [ ] **D2 词库 mmap 全覆盖**：`.qj` 已 mmap，但 TTS 解析后的 arena 仍是整份堆内存。目标：索引与词条都走 mmap，只在查到时触碰页。验收：8.7 万条词库 RSS 增量 < 5 MB。
- [ ] **D3 渲染位图复用扩到 macOS/Linux**：Windows 已做（PR #1128）；macOS 的 `CALayer`/`CGContext` 与 Linux 的 cairo 路径各查一遍，去掉每帧新建的缓冲区。
- [ ] **D4 候选窗尺寸缓存**：翻页/换主题会重建位图。把「内容尺寸 → 位图」做成小 LRU（2–3 档），减少重建。
- [ ] **D5 启动时间**：冷启动到可打字现在要等词库索引；目标 < 300 ms（词库先给前 2 万条，其余后台补）。
- [ ] **D6 长句延迟**：`performance.md` 第八轮已到平均 24 ms、最慢 101 ms；目标是 20 字长句最慢 < 60 ms（算子合并或 Q4）。
- [ ] **D7 功耗**：空闲时工人循环 1 秒一拍；检查能否降到事件驱动 + 定时器合并，减少唤醒。
- [ ] **D8 Android 内存**：键盘与宿主同进程，模型/词库按需；目标 PSS < 80 MB（现在随包 56 MB 数据）。
- [ ] **D9 学习数据落盘频率**：`LEARNING_FLUSH_INTERVAL` 与写入放大查一遍，避免每次按键都触发 fsync。
- [ ] **D10 大词库分片**：按首字母/韵母分片加载，翻页只碰当前片。
- [ ] **D11 内存回归门**：CI 加一个 `--replay` 跑 1000 条的 RSS 上限检查（超阈值 fail），防以后又涨回去。
- [ ] **D12 崩溃/泄漏排查**：`ui::painter::forget` 与 `Canvas` 的 GDI 句柄在长会话里计数，防句柄泄漏。

## E 构建与发布

- [ ] **E1 release profile 收紧**：`Cargo.toml` 现在没有 `[profile.release]`。加 `lto = "thin"`、`codegen-units = 1`、`strip = "symbols"`、`panic = "abort"`（FFI 边界已用 `catch_unwind` 的模块除外）。预期二进制小 30–40%，启动略快；代价是 release 编译变慢。
- [ ] **E2 安装包体积**：Windows 78 MB、Android 56 MB 随包数据。分词库/模型/字体三块做「必装 + 可选下载」，必装压到 20 MB 内。
- [ ] **E3 sccache**：CI 与本地都接 `sccache`，配合现有 `Swatinem/rust-cache`；先在一台机器上量命中率。
- [ ] **E4 cargo-nextest**：CI 的 `cargo test` 换 `nextest`（并行、失败重跑、超时），预计测试阶段快 30–50%。
- [ ] **E5 体积监控**：`cargo-bloat` 每次 release 出一份「最大的 20 个符号」，防某个依赖突然变大。
- [ ] **E6 依赖裁剪**：`cargo-machete` 查未使用依赖；`cargo-udeps` 查 nightly 下的无用 crate。
- [ ] **E7 双架构构建**：Windows x64 与 x86 现在分两次编；用 `--target` 矩阵并行，CI 时间对半。
- [ ] **E8 增量构建**：给 dev 加 `[profile.dev] opt-level = 1`、`debug = 1`，`cargo check` 与测试循环更快。
- [ ] **E9 PGO（可选）**：用 `--replay` 的负载做一次 PGO，量候选查询的收益；收益 < 5% 就不进 CI。
- [ ] **E10 发布签名与校验**：Windows 安装包与 macOS 公证已有流程；补 Linux 包的签名与 `sha256` 清单。
